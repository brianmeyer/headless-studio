### Real flags
- R1, runner/scout.py:24-33 and runner/__main__.py:27-36, the product CLI can never produce sourced signals: `scout()` always returns fixtures, live credentials are detected and ignored, and `--fixtures` is a no-op. That makes every real CLI run a permanent `miss`, contrary to the locked read-only scout → gated hit path and the documented “fixtures when APIs/keys are missing” fallback. Suggested fix: implement at least one bounded read-only live scout using already-present credentials, fail closed to fixtures on missing credentials/API errors, and make `--fixtures` explicitly bypass live scouting.
- R2, runner/gates.py:78-89 and runner/scorer.py:34-45, fixture evidence can satisfy the pain/intent and score gates for a mixed run. Reproduced with five non-fixture signals containing no pain/intent plus the four fixtures: verdict `hit`, score 60.8 medium, eight fixture-derived clues, and all gates passed. This is a silence-gate hole because a hit can be authorized by synthetic pain and engagement. Suggested fix: compute hit-qualifying clues, demand, intent, confidence, and promise support from non-fixture signals only; fixtures may explain a miss but must not contribute to pass conditions. Add this mixed-input regression test.
- R3, runner/pipeline.py:36 and runner/receipt.py:140-147, the locked CLI example `--out green/out` is treated as a receipt filename. If the directory exists, the runner crashes with `IsADirectoryError` instead of writing `green/out/RECEIPT.md` and the local mock under that output directory. Suggested fix: define `--out` as an output directory per the locked task, normalize it to `RECEIPT.md`, and write the hit mock beside it as `mock.html`; alternatively add a separate explicit receipt-file option and test both contracts.
- R4, runner/receipt.py:46-102, receipts omit the required how-to-re-run command. The receipt therefore does not fully satisfy the locked output contract or preserve the exact invocation needed to reproduce a decision. Suggested fix: render a shell-safe rerun command containing the topic, fixture mode when applicable, and output destination, then assert it in hit and miss tests.
